Why a CSV that looks fine still gets rejected

Almost every failed import is one of six shapes, and all six are visible in the raw text before you upload anything:

  • Column count drift. A stray comma or an unquoted " inside a product name shifts every later cell one column to the right, so the price lands in the barcode column. Rows that do not parse to the same number of fields as the header are the first thing this page reports.
  • Money that is not a number. $1,200.00, 1.200,00, 12 99 and 45 USD all look like prices to a human and like garbage to an importer. The cleaner rewrites them to a plain decimal and flags every one it changed.
  • Two date systems in one file. 04/03/2026 is April 3rd in the US and March 4th in most of Europe — the same cell, two different orders, and nothing in the file says which. Rather than pick one, this tool leaves the ambiguous cell as typed and lists it.
  • Invisible whitespace and line endings. A trailing space after a header name (Title ) makes the column "missing" to the importer, and mixed CRLF/LF breaks naive parsers. Headers and cells get trimmed.
  • Duplicate rows. The same order or the same variant shipped twice in one export creates duplicate keys, which either overwrites silently or fails on a uniqueness check.
  • A byte-order mark at the start of the file. Excel writes one, and it turns the first header into Handle with an invisible BOM in front, so the first column is not recognised at all.

Worked on Shopify, Etsy, Amazon and WooCommerce exports — the checks are the same because the failures are the same. The tool changes nothing it cannot prove, which is why the flagged list exists.
